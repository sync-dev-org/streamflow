Real-time video pipeline

Sharper live video,
right on the beat.

streamflow は、LMS などで届いた映像を GPU で超解像し、一定の周期で送り出す、実時間の映像処理の application です。入力が途切れても、処理が遅れても、出力の流れを止めません。

01Pipeline

Four threads,
two buffers, one stream.

streamflow は、一つの process で一本の stream を扱います。受信、処理、送信を別々の thread に分け、間に置いた buffer で受け渡します。どこかの段が一瞬遅れても、ほかの段は自分の周期で動き続けます。

Thread R

受信と decode

入力 module が、受信、decode、色の変換を受け持ちます。CDA-VSR を使う時は、decode で取り出した motion vector と残差 (side data) を frame と一緒に渡します。

Thread P

超解像と resize

streamflow の C++ の thread が、画像処理の library の pixtreme で色を変換し、CDA-VSR または SPANv2 で推論して、起動時に決めた出力の大きさへ揃えます。

Thread E · S

encode と送信

出力 module が、encode と送信を受け持ちます。thread S は一周期に一枚ずつ、出力の側の clock で送り出します。

Buffers

短い buffer

pre buffer と post buffer は、満杯の時に最も古い frame を捨てる drop buffer です。待ちを溜め込まず、遅れを後へ持ち越しません。二つの buffer の深さは設定 file で変えられます。

02Resilience

Drop after decode.
Never stall the output.

処理が間に合わない時、streamflow は frame を捨てて先へ進みます。捨てるのは decode の後から encode の前までに限ります。送る frame が無い周期には最後の画を送り直し、出力を途切れさせません。

  • encode 済みの data は捨てない

    受け取った data はすべて decode し、encode した後の data も捨てません。encode 済みの data は前の frame を参照するため、途中を捨てると、次の参照の起点まで受け手の画が崩れるからです。

  • 入力が途切れても待ち続ける

    入力が途切れても streamflow は終了せず、入力の再開を待ちます。その間も、最後の画と無音を同じ周期で送り続けます。

  • 途切れの後は時系列の状態を初めから

    CDA-VSR の時系列の状態は、途切れの後の最初の frame と、I frame ごとに初期化します。参照が欠けた frame も推論して送り、その数を統計に数えます。

  • 常時の連続運転

    常時の連続運転を前提にしています。停止の要求 (SIGINT、SIGTERM) を受けると、受け付けた処理を終えてから入力と出力を閉じ、統計を出して終わります。その待ちの間に二回目の停止の要求を受けると、残りの待ちを打ち切り、統計を出して 0 以外の終了 code で終わります。

03Timing

Keep the beat.
Follow the source.

出力の frame rate は入力と同じで、streamflow は frame rate を変換しません。thread S は出力の側の clock で一周期に一枚ずつ送り、届く間隔の揺れを出力へ持ち込みません。

  • 入力の到着に緩やかに追従する

    送り手の clock と出力の clock は、わずかに違います。NDI と LMS の出力では、post buffer の待ちが目標に近づくよう、送信の時刻を一周期ごとにごく小さな量だけ前後させます。この追従は既定で有効です。

    目標の待ち (既定 4 ms) と、一周期あたりに動かす量の上限 (既定 0.1 ms) は、設定で変えられます。

  • 周期が変わったら開き直す

    出力は、最初の frame が届いてから、その frame の周期で開きます。走行の途中で入力の frame 周期が変わった時は、受け付けた frame を送り終えてから出力を開き直します。開き直す間だけ、出力は途切れます。

  • LMS の受信の待ちを選ぶ

    LMS の入力では、LMS の SDK が受信の側で待つ時間 (delay_ms) を、引数か設定 file で選べます。書かなかった時は 100 ms です。

  • 処理の境目の時刻を記録する

    --stage-trace <path> を付けて起動すると、入力、thread P、出力の処理の境目の時刻を記録し、終了時に一つの file に書き出します。遅延がどの段で生じるかを調べる時に使います。

    記録は起動時に確保した配列に入れ、系列ごとに直近の n frame 分 (既定 9000、--stage-trace-records で変更) を残し、古い記録から上書きします。運転中に配列は増えません。付けずに起動した時は記録しません。

04Audio & timecode

Sound and timecode
stay with the picture.

音声と timecode は、frame と一緒に pipeline を流れます。frame を捨てる時はその音声も一緒に捨て、最後の画を繰り返す周期には無音を送ります。長く運転しても、映像と音声の対応はずれません。

  • 音声は選んで有効にする

    音声の出力は、--audio か、設定 file の output.audio.enabled で有効にします。既定では無効です。

  • timecode を引き継ぐ

    NDI へ出力する時は、出力の各 frame に、その画の元になった入力の frame の timecode を付けます。同じ画を繰り返す時は同じ値を付け、捨てた frame の値は出力に現れません。入力に timecode が無い時は、送る時の現在時刻を付けます。LMS の出力は timecode を運びません。

05Components

Choose parts by name.
Add the ones you need.

入力、出力、推論の model は、入れ替えて使う部品です。起動の引数で部品の名前を選ぶと、streamflow は導入先の directory (prefix) から、その名前の部品を探して組み立てます。

Standard

標準の構成

配布物は、LMS、NDI、CDA-VSR、SPANv2 を標準の構成として一つの prefix に入れます。部品が共有する pixtreme と core の実体は、prefix に一つずつ置きます。

Add-on

標準に無い部品を足す

標準に無い部品は、その部品の配布物を同じ prefix の決まった配置に足して使います。streamflow の配布物を作り直す必要はありません。

Preflight

最初の frame の前に確かめる

選んだ部品が導入されていない時、読み込めない時、ABI が合わない時を区別し、部品の名前と配布名を示して止まります。motion vector と残差を要する model に、それらを出せない入力を組み合わせた時も、最初の frame の前に止まります。

Lifecycle

部品より長く生きる application

application は部品より長く生き、内部では入力、出力、推論の model を走らせたまま交換できる作りです。交換を外から指示する口は今は設けておらず、設定を変える時は streamflow を起動し直します。

06Setup

Install once.
Start with arguments.

配布物は、streamflow の実行 file と標準の部品を一つの prefix にまとめた native の配布物で、deb と archive の二つの形があります。配布物を受け取り、導入の command を一回実行すれば、TensorRT を入れた host で使えます。実行に Python の環境は使いません。

  1. host を用意する

    Ubuntu 24.04 以降の Linux x86_64 (WSL2 を含む) に NVIDIA の driver を入れ、NVIDIA の CUDA の apt repository を登録します。WSL2 では driver を Windows の側に入れます。CUDA Toolkit は要りません。

  2. 配布物を導入する

    受け取った deb を apt で導入すると、prefix が /opt/streamflow に入り、streamflow の command で呼べます。apt は TensorRT の runtime と、NDI が使う Avahi を一緒に入れます。archive は展開した directory のまま使え、TensorRT は host に入れておきます。

  3. 重みを用意する

    CDA-VSR または SPANv2 の checkpoint (safetensors) を、配布物とは別に受け取ります。指定するのは checkpoint の path だけで、TensorRT の engine は部品が初回に作って cache します。

  4. 引数で起動する

    部品の名前と出力の大きさを引数で選んで起動します。部品ごとの設定は --input-option のように key と値の組で渡します。よく使う組み合わせは YAML の設定 file に保存し、--config で preset のように使い分けられます。同じ項目は引数の値を使います。

  5. 動きを見る

    運転中は進捗と動作の状況を、一行に一つの JSON で標準出力に出し、終了時に統計を出します。統計には、thread P が frame 一枚を処理した時間の件数、平均、中央値、p90、最大が入ります。

Installbash
# NVIDIA の CUDA の apt repository を登録した後
$ sudo apt install ./streamflow_X.Y.Z_amd64.deb
$ streamflow --help
Runbash
$ streamflow --config live.yaml \
    --input lms --input-option connection.channel=1 \
    --arch cda-vsr --model ./weights.safetensors \
    --output ndi --width 1920 --height 1080 \
    --audio

Windows から起動する — 配布物には、Windows から WSL の中の streamflow を一回の操作で起動する batch file が、CDA-VSR 用と SPANv2 用に一つずつ付きます。使う model の batch file に LMS の ID、channel、delay_ms を渡すと、LMS の入力から ×2 の推論を経て NDI の出力へ送る引数を組み立てて起動します。WSL の distro の名前と重みの path は、batch file の先頭で変えられます。
